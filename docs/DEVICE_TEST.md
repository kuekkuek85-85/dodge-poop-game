# 실기기 점검 절차

컨테이너 안에서 확인할 수 있는 것은 다 확인했다(자동 검사 50개, 브라우저 시뮬레이션,
28명 동시 접속). 남은 것은 **진짜 배포된 주소를 진짜 태블릿에서 만지는 것**이다.
여기서만 드러나는 것: 실제 터치 감도, 학교 와이파이 속도, 태블릿 화면 크기,
그리고 난이도가 실제로 재미있는지.

배포 방법 자체는 [`README.md`](../README.md#배포-firebase--vercel)에 있다. 이 문서는
배포한 다음 **무엇을 어떤 순서로 만져 볼지**만 적는다.

---

## 0. 배포 전에 반드시 확인할 것 하나

Vercel 환경변수 `TEACHER_CODE`를 **`123456`이 아닌 값**으로 설정한다.

`123456`은 이 저장소 문서에 적혀 있다. 저장소가 공개돼 있으면 누구나 교사 화면에
들어와 **전체 기록을 지울 수 있다**. 로컬 개발에서만 기본값으로 쓰이고, Vercel에서는
값을 안 넣으면 교사 API가 아예 동작하지 않게(fail closed) 해 뒀다.

수업 당일 교사 두 명이 같은 코드를 써야 하니, 정한 값은 따로 메모해 둔다.

## 1. 배포 직후 — 컴퓨터 브라우저에서 1분

| 확인 | 방법 | 통과 기준 |
|---|---|---|
| 페이지가 뜨는가 | `https://<프로젝트>.vercel.app` | 학번 입력 화면 |
| 저장이 되는가 | 한 판 하고 죽기 | "기록이 저장되었습니다." |
| Firestore에 들어갔는가 | Firebase 콘솔 → Firestore | `records`, `students`, `boards` 세 개가 생김 |
| 교사 화면 | `.../teacher` + 새 코드 | 방금 기록이 보임 |
| 코드 틀리면 막히는가 | 아무 숫자나 입력 | 거부됨 |

여기서 막히면 대개 환경변수 문제다. Vercel → 프로젝트 → Logs 에 원인이 그대로 찍힌다.

## 2. 태블릿에서 — 학생이 겪는 순서 그대로

**되도록 수업에 쓸 그 태블릿, 그 교실 와이파이로 한다.** 이게 이 점검의 핵심이다.

### 2-1. 첫인상

- [ ] 링크를 열었을 때 **몇 초 만에** 입력 화면이 뜨나 (교실 와이파이 기준 3초 이내면 좋다)
- [ ] 학번·이름 입력칸을 눌렀을 때 키보드가 화면을 가리지 않나
- [ ] 이름칸에 한글이 제대로 들어가나

### 2-2. 조작

- [ ] 화면 **왼쪽/오른쪽을 누르면** 캐릭터가 그쪽으로 가나
- [ ] **손가락을 끌면** 캐릭터가 따라오나
- [ ] 손가락이 캐릭터를 가려서 안 보이지는 않나 ← 태블릿에서만 알 수 있다
- [ ] 게임 영역이 화면에 꽉 차되, 찌그러지지 않았나
- [ ] 태블릿을 **가로로 눕혀도** 게임이 정상인가

### 2-3. 난이도 ← 가장 중요

같은 태블릿으로 **다섯 판** 해 보고 적는다.

| 판 | 생존 시간 | 점수 |
|---|---|---|
| 1 | | |
| 2 | | |
| 3 | | |
| 4 | | |
| 5 | | |

판단 기준 (1학년 기준):

- 첫 판이 **10초도 못 간다** → 너무 어렵다
- 한 판이 **2분을 넘어간다** → 너무 쉽다. 수업 시간에 회전이 안 된다
- **20~60초** 사이에서 대부분 끝나면 적당하다

바꿀 값은 `public/js/shared/difficulty.js` 한 파일에 다 모여 있다
(README의 "난이도 조정" 참고). 숫자만 바꾸고 다시 배포하면 된다.

### 2-4. 저장과 순위

- [ ] 죽은 뒤 결과 화면에 점수·시간·등수가 나오나
- [ ] "기록이 저장되었습니다."가 뜨나
- [ ] 대시보드에 내 이름이 **가운데 글자만 가려진 채**로 보이나 (김○늘)
- [ ] 두 번째 판이 첫 판보다 낮으면, 순위표에는 **높은 쪽**만 남나

### 2-5. 태블릿 돌려쓰기 ← 실제 수업에서 반드시 생긴다

앞 학생이 하고 다음 학생이 이어받는 상황이다.

- [ ] 앞 학생 정보가 입력칸에 남아 있나 (남아 있는 게 정상)
- [ ] 그 위에 **다음 학생 정보로 고쳐** 넣고 바로 시작 → 기록이 **뒷사람 이름으로** 저장되나
- [ ] 순위표에 앞사람 이름으로 잘못 올라가지 않았나

### 2-6. 연결이 끊기면

- [ ] 게임 중에 **와이파이를 끄고** 죽어 본다 → "잠시 후 다시 저장합니다" 안내가 뜨나
- [ ] 와이파이를 다시 켜고 한 판 더 한다 → **아까 기록도 같이** 올라가나

---

## 3. 여러 명이 한꺼번에 — 가능하면

교사 두 명 + 태블릿 몇 대로도 대략 볼 수 있다. **같은 반 번호**로 동시에 죽는다.

- [ ] 전원 저장되나 (한 명도 빠지지 않아야 한다)
- [ ] 교사 화면 순위표에 전원 보이나
- [ ] 너무 빨리 연속 저장하면 "잠시 후" 안내가 뜨나 (5초 간격 제한 — 정상 동작이다)

한 반 28명 동시 접속은 에뮬레이터로 이미 확인했다(84건 전부 저장, 오류 0). 실기기
확인은 **와이파이**가 버티는지를 보는 것이라 목적이 다르다.

---

## 4. 교사 화면 — 수업 전날 리허설

- [ ] 반 선택 → 순위가 5초마다 저절로 갱신되나
- [ ] **투사 모드** 버튼 → 관리 버튼이 사라지고 글씨가 커지나
- [ ] 교실 **TV/프로젝터**에 띄웠을 때 뒷자리에서 이름과 점수가 읽히나 ← 실제 교실에서만 알 수 있다
- [ ] 반 인원 수를 넣으면 미참여 번호가 맞게 나오나
- [ ] CSV 내려받기 → 엑셀에서 한글이 깨지지 않나
- [ ] 이상 기록 보기에 뭔가 잡히나 (없는 게 정상)

**초기화는 리허설 때 한 번 해 보고, 수업 당일에는 손대지 않는다.**

- [ ] 반 기록 초기화 → 확인 문구를 입력해야만 실행되나
- [ ] 초기화 후 순위표가 비고, 새로 한 판 하면 다시 쌓이나

---

## 5. 결과를 알려 주는 방법

고칠 게 나오면 이 정도만 적어 주면 된다.

- **무엇을** 했더니 (예: "태블릿 가로로 눕히고 시작")
- **무엇이** 됐나 (예: "캐릭터가 화면 밖으로 나감")
- 기기 (예: "갤럭시탭 A9, 크롬")

난이도는 2-3의 표를 그대로 주면 바로 조정할 수 있다.

---

## 남아 있는 한계 (알고 있는 것)

- **참여 인원**은 유효한 기록이 1개 이상인 학생만 센다. 들어와서 아직 안 죽은
  학생은 미참여로 나온다.
- `GET /api/records?key=...` 는 로그인 없이 열린다. 점수만 나오고 이름은 나오지
  않아 의도한 대로 뒀다.
- 이름은 서버에 **그대로** 저장된다(가리는 건 보여 줄 때만). 학기 끝나면 교사
  화면의 **전체 기록 삭제**로 이름까지 지운다.
